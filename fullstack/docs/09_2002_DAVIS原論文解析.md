# 2002年 DAVIS原論文解析

対象: `davis.pdf`

論文: Moon Yul Huh, Kwangryeol Song, "DAVIS: A Java-based Data Visualization System"

## 1. このPDFの位置づけ

このPDFは、後年の `LINE MOSAIC PLOT.pdf` の参考文献[9]にある2002年の Computational Statistics 論文と、タイトル・著者・内容が一致する。`LINE MOSAIC PLOT.pdf` は同論文を `Computational Statistics, 17(3), 411-423` と引用している。

PDFメタデータ上の作成日時は2002-08-21で、本文のページ番号は1-12となっているため、出版社版のページ番号を振った最終誌面そのものというより、著者側の公開用PDF／著者稿である可能性が高い。ただし本文はDAVISの原典として扱える。

## 2. 最重要の新事実: ソースコードは公開されていた

p.2-3でDAVISについて次の記述がある。

> `Davis is written in pure Java language, and the source is available to the public.`

さらに、各コンポーネントはJava Beanとして実装され、再利用しやすいようにしたと説明されている。

これはクローン計画にとって重要である。現在ソースを発見できていないだけで、当時はソースコード公開を意図したプロジェクトだったことが原論文から確定する。

### 追加探索すべきURL

原論文末尾(p.12)には、DAVISのWebサイトとして次の表記がある。

`http://stat.skku.ac.kr/~myhuh/softwares/Davis.html`

既に調査していた `/software/DAVIS/` や `/myhuh/DAVIS.html` と異なり、`softwares` が複数形で、`Davis.html` の大文字小文字も異なる。このURL系統はWayback/CDX探索の追加キーとする。

## 3. DAVISが目指したもの

原論文では、データ可視化を単なる静的グラフとしてではなく、パラメータ変更やデータ操作に対してリアルタイムに反応するman-machine interactionとして定義している(p.2)。

したがってDAVISの本質は「グラフの種類の多さ」ではなく、共通データ状態を複数ビューが共有し、操作結果が即時伝播する点にある。

## 5. Linked brushingの原仕様

p.9の記述は非常に具体的である。

1. 開いているplot上でmouse brushingによりデータ点を選択
2. 選択点は赤でhighlight
3. 選択によりデータが「selected」と「not selected」の2群に分かれる
4. 選択状態で右クリック
5. Focus / Delete / Identify を選択
6. 操作結果は開いている他のtoolへ即時伝播

この「選択集合を共有状態として保持し、右クリックで集合に対する操作を行う」モデルはPCPクローンで忠実に再現すべき重要仕様である。

### 重要な訂正: Histogram/Boxplotは初版では選択元になれない

原論文p.7, p.9, p.11は、初版ではmouse brushingがHistogramとBoxplotに実装されていないことを明記している。

ただし両plotはselection/clusteringの「結果を受け取る」ことはできる。

- Histogram: 各binをgroupごとの色に分割
- Boxplot: groupごとの複数boxplotへ分割

したがって、以前の調査で「Boxplotから外れ値を選択しPCPへリンク可能」と扱った記述は、少なくとも2002年初版については確証がなく、訂正が必要である。

## 6. Parallel Coordinatesの原仕様

原論文でPCP固有機能として確定できるのはp.11の次の2系統である。

### Direction

- Horizontal
- Vertical

### Arrangement

- database arrangement
- component method arrangement
- permutation arrangement

後期GUI資料で見える `NoOrder / ComponentOrder / PermuteOrder` は、この3方式の後期UI上の名称と考えるのが自然である。

### Figure 3から確認できること

p.5 Figure 3はIrisデータのPCPを、

- database順
- component method順

で比較している。

lower figureでは軸順そのものが大きく変わり、component methodが単なる色付けやscale変更ではなく「変数の並べ替え」であることが視覚的にも確定する。

またIrisの `class` 変数がPCP軸として描かれているため、初版DAVISのPCPは連続値だけではなく、少なくともこのような離散カテゴリ変数も軸に載せていたことが画面から確認できる。ただしカテゴリを縦位置へ写像する厳密な規則は本文に記載されていない。

## 7. Arrangementアルゴリズムの位置づけ

原論文は、PCPで変数順が理解しやすさを大きく左右すると問題設定したうえで、自動配置アルゴリズムが必要だとしている(p.4)。

component method / permutation methodの詳細は `Huh et al. (2001b), Variable Arrangement for Visual Clustering` に委ねている。既にDAVIS-PCPフォルダに保存済みの `2001_Algorithms_for_Grand_Tour_and_Parallel_Coordinates.pdf` は、この系統の実装復元資料として扱う。

## 10. PCPクローン設計に直接反映すべき事項

### DAVIS互換として必須

1. database / component / permutation の3軸順
2. horizontal / vertical
3. mouse brushingによるselected set生成
4. selected setの赤highlight
5. Focus / Delete / Identify
6. 操作結果のlinked views即時伝播
7. clustering groupの色伝播
8. categorical axisの取り扱い

### 現時点では未確定として残す

- PCPでのbrush gestureの幾何形状（矩形なのか、lassoなのか、線直接選択なのか）
- Focusの厳密なデータ状態遷移
- Deleteが一時非表示かデータモデルからの削除か
- Identifyで表示する情報とUI
- categorical axisの順序決定規則
- jittering（2002原論文には記載なし。後期資料では確認されるため「後期DAVIS仕様」として分離する）

## 11. 既存調査への訂正・強化

- 「ソース未発見」→ 現在未発見だが、原論文上は当時 `source is available to the public` と確定。
- 「Boxplotからもbrush」→ 初版では不可。Boxplotは他ビューからのgrouping結果を受け取る側。
- PCPの3軸順 → 原論文で明確に確定。
- Direction horizontal/vertical → 原論文で明確に確定。
- Jitter → 初版では未確認。後期版仕様として扱う。
