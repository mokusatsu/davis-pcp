# 分析作業の保存・再開と入力の対応

## 共通分析対象の保存

ヘッダーの **Save** は、現在のデータセットに対する対象行・選択行・標本と抽出来歴・使用変数・グループを保存する。個別分析ページの入力や計算結果は保存対象に含まれない。

- 同じデータセットの同じセッションは更新し、名前も更新する
- データセットを切り替えた後の Save は新規セッションになる
- **Save As** は名前を確認して別セッションを作成する
- **セッションを開く** から保存済み一覧を選ぶと、対応するデータセットを読み込み、保存時のデータ・スキーマ世代と対象行を検証してから復元する
- 世代不一致、不完全な記録、削除されたデータセット、読込失敗では現在の作業を変更しない。旧記録から対象を推測して復元しない
- 保存中は重複送信・閉じる操作・データセット切替を止める。失敗時は名前を残し、エラーを表示して再試行できる
- 競合時は現在の入力を保持する。「保存済みを開き直す」か「コピーとして保存」を明示的に選ぶ。Cancel は保存しない

API の PUT /sessions/{id} は直前の GET/POST/PUT で返された versionToken を必須とし、古い token は SESSION_CONFLICT、欠落は SESSION_VERSION_REQUIRED で拒否する。セッションの datasetId と snapshot の datasetId が一致しない書込は SESSION_DATASET_MISMATCH で拒否し、既存データと revision は変更しない。

## 入力と結果

- Statistics は現在の対象・世代で成功した集計だけを表示する。失敗時は旧対象の値を隠し、エラーと再試行を示す
- KDA から Penalty-Reward へは実行時の目的変数・説明変数・要求対象行・世代を引き継ぐ。両方式は共通のコードブック欠損規約に従い、要求対象行数と欠損除外後の有効行数を分けて表示する。Penalty-Reward は別の推定方法であり、KDA 重要度の頑健性検証を意味しない
- KDA 重要度の Robustness 検証は未対応のため実行できない。全体平均の頑健性結果で代替しない
- KDA/PRA の数値候補はデータ・スキーマ変更に追随し、有効な入力は保つ。目的変数・説明変数・対象行の不足は実行前に示す
- OLS と正則化回帰は方式を往復してもそれぞれの入力・結果を保つ。非表示方式の補助的な取得・描画は止める
- Grand Tour は選択した全投影列で観測された有限値のある行を使う完全ケース方式。欠損コードを含む欠損・非数値・無限値の行は除外し、投影行数・除外行数を示す。欠損を実測 0 に置き換えない
- Sampling の seed は 0 以上 9007199254740991 以下の整数（空欄は新しい乱数）とし、不正な入力は欄の近くに理由を表示する。API も同じ境界を検証する

## 検証

通常のフロントエンド・バックエンド試験に加え、scripts/check_workflow_runtime.py は隔離した組込み Iris で HTTP/SQLite の保存整合性、競合、seed 検証と修正後の再現性を確認する。

オフライン Pyodide バンドルがある場合は scripts/check_workflow_pyodide.mjs にその pyodide ディレクトリを指定すると、同じ ASGI 検証を実際の WASM で実行する。外部サイトの保存データは使用しない。
