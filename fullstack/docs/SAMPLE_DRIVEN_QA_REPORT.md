# 実サンプル検証・修正記録（2026-10-05）

## 対象と現在地

開始版は `1c4cc88`、対象は12種類の組込みサンプル。検証計画は [SAMPLE_DRIVEN_QA_PLAN.md](SAMPLE_DRIVEN_QA_PLAN.md) を参照。

この記録は「全機能が合格」という意味ではない。数値・API・GUI・実ファイル・静的WASMを分けて確認し、下の残件から次の検証を進める。最初の修正群について、公開後の確認までは公開済みと扱わない。

## 第1修正群で確認した問題

### 1. コードブックの有効範囲外の値が分析へ混入（高）

掛川の「満足度01」の有効カテゴリを1～3に変更すると、48件の回答4が無効値であるにもかかわらず分析へ戻されていた。有効回答は294件だが分析入力は342件になり、逆転時の平均も1.65646から2.65646へずれた。横浜の名義尺度でも見出し件数と有効回答数が一致しなかった。

明示されたカテゴリ順を有効範囲の正本とし、順序/数値/名義尺度で同じ行を除外するよう修正。平均だけでなく標準偏差・分位点・度数も同じ正規化済み値から算出する。FEDF、SparsePCA、EFA、回帰、FAMD、サブグループ探索、モザイクの関連経路も再検査した。

追加の境界検査では、有効カテゴリが欠損コードだけになった場合に未知の回答を有効へ戻さないこと、欠損/非該当/無効を区別すること、入力の生値を変えないことを確認。掛川3変数の共通有効行は、1～3の範囲で200件、元の1～4では252件。逆順の明示対象でも、各サービスの行IDと値の対応を確認した。

### 2. 最尤因子分析の初期独自性が仕様と逆（中）

初期値の計算で逆数を二重に取っていたため、相関のある項目でも初期独自性が上限付近になっていた。EDSSの先頭6項目では、仕様上約0.41～0.48の初期値がすべて1になった。

仕様の `clip((1 - 0.5*q/p) / diag(inv(R)), lower, 1)` に修正し、逆行列計算に失敗した場合の従来の保守的な初期値は維持した。EDSS両標本とATOPPの6項目・1/2因子で比較し、6ケース中5ケースで反復数が減少した。十分な反復後の目的関数は比較した全ケースで一致しており、「過去の最終負荷量がすべて誤りだった」とは結論していない。

### 3. クロス集計CSVの列ずれと負数の文字列化（中）

Siechniceの属性1×選択の実ダウンロードで、13列の見出しに対し全10データ行が15～19列へ崩れた。原因は、ラベル中のカンマ・引用符をCSVとして引用していないこと。負の調整済み残差にも文字列用のアポストロフィが付いていた。

データと来歴のCSVセルを適切に引用し、引用符・改行を保持するよう修正。式注入対策は文字列に適用し、型付きの負の数値は数値として出力する。実際のポーランド語ラベル、多行の来歴、式の先頭文字を使った回帰を追加した。

「残」は未実施、「門」は仕様に基づく非対応、「限定」は記載範囲で合格を意味する。

## 再実行

固定依存を入れたPythonで、通常テスト（`backend/tests/unit` と `backend/tests/api`）、統計監査（`backend/tests/stats_tests`）、調査監査（`backend/tests/survey_audit`）を**別プロセス**で実行する。監査の隔離規約により、全ディレクトリを一つのpytestプロセスへ混在させない。

フロントは `npm test`（graph-core WASM資産を先に用意）、型は `tsc --noEmit`。今回の静的受入は `scripts/check_sample_campaign_runtime.py` と `scripts/check_sample_campaign_pyodide.mjs` で再実行できる。後者には既存のオフラインPyodide資産ディレクトリを指定する。
