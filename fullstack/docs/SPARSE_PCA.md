# SparsePCA

PCAページの「SparsePCA」で、数値変数の疎な成分を学習できます。通常PCAとは独立した解析で、通常PCAの計算・表示は変更しません。

## 入力

- 共通の対象行（All / Active / Selected / Sampled）と変数選択を使用します
- 数値の間隔・比率尺度を使用できます。順序尺度は固定した `categoryOrder` の1..m順位得点として扱うことへの承認が必要です。多重回答、名義尺度、ID、ウェイト列は分析変数にできません
- コードブックの欠損コード、順序、逆転を適用した分析値に対し、選択した全変数の共通有効行を確定します。その集合内の定数列だけを除外します。全欠損列を黙って落として対象行を増やすことはありません
- 現在の補完値を使い、採用した補完セル・行数を結果に記録します
- 調査ウェイト・頻度ウェイトは未対応です。保存済みウェイト設定を使用する要求は拒否します。「非加重」を明示的に選択すると、ウェイト欠損・ゼロや無関係な調査設計列によって対象行を除外しません

## 設定

標準化（correlation）は、分析値を学習行内の平均と標本標準偏差（ddof=1）で変換します。中心化のみ（covariance）は、元の分析値の単位を保ちます。内部で勝手に標準化へ切り替えません。

`alpha` はscikit-learn SparsePCAのL1係数そのものです。標本数、変数の単位、前処理を変えると意味が変わります。独自のn正規化を行いません。`ridgeAlpha` は学習後の得点計算を安定化する係数で、Bを疎にするalphaとは別です。

成分数は実際の同時学習設定です。最大成分数で学習して先頭だけを切り取る処理ではありません。成分の表示軸は学習済み結果から選択します。1成分も利用できます。

初期版はLARS、単一ジョブ、固定した乱数seedを使用します。別solverへの自動切り替え、MiniBatch、CV、白色化はありません。alpha=0もSparsePCAとして計算し、ridgeAlphaが正なら得点が縮みます。通常PCAへの自動切り替えではありません。

### 計算規模

共通有効行数n、定数除外後の変数数p、成分数kについて、n≤10,000、p≤100、k≤20です。さらに `max(n,500) × p × k × maxIterations ≤ 150,000,000` を満たす必要があります。反復回数は1〜5,000、成分数は `min(n-1,p)` 以下です。

範囲を超える場合は計算を開始せずエラーを返します。対象行、変数、成分数または反復上限を明示的に減らしてください。これはブラウザーでの長時間計算を抑える経験的な上限で、処理時間の保証ではありません。収束が遅い設定では反復上限を減らすと未収束になることがあります。

## 表示値の意味

学習に用いる中心化済み行列をZcとすると、以下を区別します。

- **疎な再構成係数B**: sklearnの `components_`、k×p
- **得点計算係数W**: p×k。実際のridge最小二乗変換と一致する係数
- **得点T**: `Zc @ W`
- **再構成**: `T @ B`
- **変数–得点相関**: 同じ学習行上で、コードブック変換後の分析値とTの直接Pearson相関
- **成分間相関**: Tの列どうしの直接Pearson相関

Bは一般に直交しません。Bのある係数が0でも、Wの対応する係数や変数–得点相関が0になるとは限りません。SP1、SP2…の順序は学習器の返却順で、分散降順ではありません。

実変換再構成率は `1 - ||Zc - T @ B||² / ||Zc||²` です。標準化なら標準化空間、中心化のみなら元の分析値を中心化した空間で、学習行について算出します。非直交な成分の分散を足し上げる指標ではありません。固有値、通常PCAの寄与率・累積寄与率、Kaiser基準、相関円は表示しません。

疎性比率はBの厳密なゼロ係数数を全係数数で割った値です。丸め表示で0に見える値とは区別します。定数・全ゼロ得点の相関は0や1で補わず、定義不可と理由を表示します。

### 収束

`sklearn.error_` の学習目的関数履歴から、許容誤差到達、反復上限、目的関数の増加を区別します。sklearnが警告を出さなくても、反復上限だけで終了した結果を収束済みとは扱いません。許容誤差到達も大域的最適解の保証ではありません。

この学習目的関数は、学習途中の辞書因子に対するものです。返却された単位長Bとridge変換Tから作った損失とは異なり、実変換再構成率とは別の診断です。

## 保存・操作・出力

結果は実行時のデータ世代、コードブック、対象行、設定、前処理と結びつけて保存します。後から入力や表示ラベルを変更しても、完了結果の係数や名称を書き換えません。実行中にデータ・コードブック・補完情報が変わった場合は、その結果を公開しません。

大きいオフセットに小さい差が含まれるデータの精度を保つため、中心化は保存した基準値 `inputAnchor` との差を先に計算します。正本の変換は `((A-inputAnchor)/inputMagnitude - normalizedMeanOffset)` で、標準化ではさらに `normalizedSampleSd` で割り、中心化のみでは `inputMagnitude` を戻します。差そのものが表現範囲を超える場合は安全な因数分解を使います。従来形の `normalizedMean` や元単位の平均・標準偏差は補助表示で、単純な生値の二乗や桁落ちする引き算から変換を作り直しません。

得点散布図は共通selection/hover、L1/L2色分け、矩形選択、点クリックと選択メニューを使用します。1成分時はSP1のみを示し、架空のSP2を作りません。重なった点を数値jitterで別の値へ動かすことはありません。

取消は結果の受け取りを取り消す論理取消です。静的版のPython計算を強制停止しません。計算が実際に終わるまで、追加のSparsePCA実行を積み上げないようにします。

CSV/JSONで再構成係数B、得点計算係数W、直接相関、診断、得点行を出力できます。JSON manifestには設定・前処理・変数定義・診断・意味説明を含めます。丸めは画面表示のみで、保存・出力は計算精度を保ちます。CSVの文字列は数式実行を防ぐエスケープを適用します。

新規行への予測・射影API、列のmaterialize、外部言語向け実行コード生成は初期版の対象外です。

## 開発者向け検証

通常のbackend/frontendテストにSparsePCAの数値・契約・ライフサイクル回帰を含めています。独立したAPI経由のoracle検証は次のスクリプトで実行できます。

```sh
PYTHONPATH=fullstack/backend python scripts/check_sparse_pca_runtime.py
node scripts/check_sparse_pca_pyodide.mjs /path/to/shipped/pyodide
# ビルド済みbackendそのものを検証する場合:
node scripts/check_sparse_pca_pyodide.mjs /path/to/shipped/pyodide /path/to/backend_app.zip
```

後者は既存のオフラインPyodide 0.27.7 / sklearn 1.6.1 bundleを使用します。新しいダウンロードは行いません。backendは本番と同じrootのstatic packagerで梱包し、公開Irisデータを分離workspaceのASGI import→fit→get/rows/select/exportへ通します。結果は `.temp/sparse-pca/` に出力します。実ブラウザーのポインター操作・表示回帰はこの数値スクリプトとは別に検証します。
