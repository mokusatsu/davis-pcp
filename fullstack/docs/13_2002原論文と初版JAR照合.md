# 2002原論文と提供初版JARの照合

目的: `davis.pdf` の記述と、既存の `08_初版JAR_バイトコード解析と互換アルゴリズム設計.md` を照合し、「論文上の意図」と「提供初版JARの実際の挙動」を分離する。

## 1. 一致している中核仕様

|項目|2002原論文|提供初版JAR解析|結論|
|---|---|---|---|
|PCP orientation|Horizontal / Vertical|orientation処理あり|初版互換必須|
|PCP ordering|database / component / permutation|NoOrder / ComponentOrder / PermuteOrder|同一3方式とみなせる|
|linked brushing|全plotへ伝播|`PlotData.index[]`共有|思想と実装が一致|
|selection group|selected/non-selected|`index=1` / `index=0`|実装レベルで対応|
|Delete / Focus|右クリック操作|共通`DavisPlot` popup|一致|
|group color|cluster/brush結果を色で伝播|`DavisColor` + group index|一致|

## 2. 原論文では不明、JARで確定したPCP仕様

### 2.1 Brush gesture

原論文は `mouse brushing` としか書いていない。

JAR解析では:

- dragで矩形selection boxを作る
- rowのpolyline全体との矩形交差判定ではない
- 各rowの「各軸上のvertex」のどれか1点が矩形内なら選択
- 線分だけが矩形を横切っても選択されない

と確定した。

これは現代の軸範囲brushとは異なる、DAVIS固有の選択semanticsである。

### 2.2 Delete

原論文: selected dataをDelete可能。

JAR:

- `index == 1` のrowをworking graphics datasetから除去

### 2.3 Focus

原論文: selected dataをFocus可能。

JAR:

- `index == 0` を除去
- non-zero groupを残す

従って単に「selected==1だけ残す」ではなく、クラスタ等で2以上のgroup indexが既に存在する場合、それらも残る。

### 2.4 Undo

原論文本文のgeneric operationではFocus/Delete/Identifyが中心で、Undoは明示されていない。

提供初版JARにはUndoが存在する。

- 多段historyではない
- `CurrentDataSet` を `GraphicDataSet` に戻す
- group indexを全0へ戻す

従って「working graphics datasetを解析開始状態へ戻す」に近い。

### 2.5 Identify

原論文はIdentifyを共通操作として説明する。

JARではPCP自体の`drawLines()`にIdentify時のrow label描画処理が確認できない。

従って:

- selection/groupingは共有される
- Identifyという共通モードはある
- PCP上で直接row labelを表示したとは限らない

という区別が必要。

## 3. Jitteringの時系列が明確になった

2002原論文ではPCPのtool-specific featureとしてDirectionと3種Arrangementのみが説明され、Jitteringは記載されていない。

一方、提供初版JARにはJittering checkboxと計算コードが存在する。

従ってJitteringは少なくとも:

`2002原論文 → 2003頃の提供初版JAR`

の間に追加された機能と扱うのが安全。

さらにJAR解析では:

- raw cellへ一様乱数 `[-0.1,+0.1)` を加える意図
- しかしpaint時に元データから`setParaData()`し直すためjitter値が上書きされる

ことが判明しており、提供初版JARでは実質的に壊れている。

よってクローンでは:

- `INITIAL_JAR_COMPAT`: バグ込み互換を必要に応じて再現
- `MODERN_CORRECTED`: 意図されたjitterを正常実装

を分ける。

## 4. Orderingも「論文」と「JAR実装」を分ける必要がある

原論文はComponent Method / Permutation Arrangementの存在と目的を説明するが、細部は別資料に委ねる。

JAR解析により:

- PermuteOrderは全順列探索ではない
- ComponentOrderは単純なPCAの逐次適用と異なる「二段相関」挙動を持つ

ことが判明している。

従ってクローンには少なくとも:

1. `PAPER_INTENT` / 文献準拠
2. `INITIAL_JAR_COMPAT` / バイトコード互換
3. `MODERN_CORRECTED` / 現代的修正版

の区別が必要。

## 5. Linked brushingの「immediate」の実態

原論文では操作が他toolへ `immediately propagated` と説明される。

JARでは各plotが共有`PlotData.index[]`を独自threadで約1秒ごとに監視するpolling方式だった。

つまり:

- UX上の契約: ほぼリアルタイムに全ビューへ反映
- 実装方式: 1秒polling

である。

現代クローンではpollingを再現する必要はない。React store/event-driven state等で即時同期し、ユーザーに見えるsemanticsだけを互換にするのが妥当。

## 6. Line Mosaic Plotとの時系列

`LINE MOSAIC PLOT.pdf` は2004年で、本文に「DAVISへ実装」と明記される。

提供初版JARのentry timestampは主として2003-04頃であるため、Line Mosaic Plotは少なくとも「2002原論文より後」の拡張機能として扱う。

このJARにLine Mosaic Plotが含まれるかどうかは、この照合文書では断定しない。必要ならJAR実体のclass/package検索を別途行う。

## 7. 設計文書で採用すべき証拠ラベル

- `PAPER-2002`: 2002原論文で確認
- `JAR-INITIAL`: 提供初版JARのbytecodeで確認
- `DAVIS-2004+`: Line Mosaic / eDAVIS等の後期資料で確認
- `INFERRED`: 複数証拠から推定
- `MODERN`: クローン側の追加仕様

「DAVIS互換」という1ラベルにまとめないこと。
