## 1. 検証の順序

1. S0: 変更前の代表不具合を再現し、通常時の操作と期待する選択rowIdを記録。
2. S1: 共通コンポーネントの対象限定unit/integrationと、SVG/Canvas/HTML/混合描画の実ブラウザ検証。
3. S2/S3: 移行したグラフ群だけの操作・状態・座標検証。
4. S4: 旧拡大の参照と対象外入口の撤去確認、表の通常回帰。
5. S5: 全51移行単位と全12対象外分類の確認。変更範囲が合格してから必要な全体回帰を実施。
6. S6: 通常buildを実行し、更新した配信物をrun-production.batから確認。build・テスト完了までが実装スコープであり、追加のビルド指示を待たない。

バックエンド統計全体テストを初手に実行しない。統計コードを変更しない本タスクで、無関係な失敗を修正範囲へ取り込まない。静的解析・unitでブラウザのレイアウトや座標が正しいと結論しない。

## 2. 環境・データ

- 実ブラウザ: 実行環境のChromium系ブラウザのバージョンを記録。サポート対象が複数なら同じ代表ケースを追加する。
- 画面サイズ: 1280×800、1920×1080、800×600。
- DPR: 1と2。ブラウザ表示倍率: 100%を基本とし125%でも代表座標ケースを実施。DPRとブラウザ倍率を同一変数とみなさない。
- 小規模fixture: 原点付近・中央・四隅に既知の座標と一意rowIdを置く。重なりを避け、矩形で選ぶ集合を事前固定する。
- 集約fixture: 値域・カテゴリと所属rowIdが既知のデータ。列名とラベルが異なる列、MA、欠損を含める。
- 分析fixture: PCA、クラスタ、木、ロジスティック、判別、CA/MCA/FAMD、重回帰、EFA、Conjointの結果を各ページの現行経路で生成する。既存fixtureを優先し、必要な追加fixtureはグラフ操作に必要な最小データとする。
- モード: Conjointはratings/choice/ranking、FAMDは4図、MCAは2図、Distributionはcards/boxplot/qqplotをそれぞれ確認する。
- 大きい図: 長い軸のPCP、多変量PCA行列、カテゴリ数の多い行列、長い木、設問一覧。実データの行列数・設定を記録する。
- dataset切替: 通常データ→列数の多いデータ→全欠損列を含むデータ。解析ができない図は通常の空表示を確認し、空の拡大状態が残らないことを検証する。
- 前処理Modal: 未確定の入力を変更した状態でG50/G51を開き、拡大終了後の入力値が一致することを確認する。

## 4. ポインタの実測手順

1. fixtureの点・ビン・セルを事前に選び、期待rowId集合を固定する。実装のhit test関数で期待値を作らない。
2. 対象を通常表示し、画面上でクリック・hover・矩形ドラッグする。合成dispatchEvent/fireEventではなくブラウザの実ポインタAPIを用いる。
3. 拡大してフィット、50%、75%、100%、125%、150%、200%、300%、400%を順に設定する。
4. 各倍率で中央と端付近の既知対象を操作する。125%以上はスクロール前後も確認する。SVGは縦横比の異なるviewportで余白が出るケースを含める。
5. 画面座標から得た論理座標を描画変換で画面へ戻した差を測定し、各軸1 CSS px以内であることを確認する。独立したfixtureの点選択結果も必ず確認する。
6. point/hoverのIDと矩形のrowId集合を通常表示の期待値と比較する。件数一致だけでは合格にしない。
7. 既存の画面pxの許容範囲・ドラッグ閾値について、閾値内外を倍率別に操作し同じ判定となることを確認する。
8. 長いPCPや行列では内側スクロールと外側スクロールを個別・併用して確認する。
9. DPR2、ブラウザ125%、画面リサイズで代表4系統を再確認する。
10. スクリーンショットにはdrag中の矩形と実際の対象が写る状態を保存する。

対象V05は各G行で行う。ただし同一rendererの詳細な行列試験は共有できる。共有する場合も各G行の入口・操作可能状態・代表の座標操作は確認し、共有元テストIDを明記する。

## 5. 自動テストの配置と粒度

| 予定ファイル | 内容 |
|---|---|
| fullstack/frontend/tests/graphExpansion.test.tsx | session、登録/解除、host同一性、StrictMode、route/dataset無効化、復帰、解析リクエスト増分 |
| fullstack/frontend/tests/graphCoordinates.test.ts | SVG/Canvas変換の境界・無効寸法・null CTM・DPR非乗算。jsdomではCTMを制御し実画面の代替としない |
| fullstack/e2e/test_focus_zoom.py | 台帳の全対象入口、倍率・実寸法・スクロール・戻す・対象外撤去 |
| fullstack/e2e/test_zoom_mouse_precision.py | 実ポインタ、rowId集合、SVG余白、混合描画、内外スクロール、DPR |
| 必要な既存ページ別テスト | 旧モック参照の更新、タブ到達・動的結果・表通常表示の限定回帰 |

unitは対象ファイル指定で開始する。例えばfrontendをcwdとしてnpm run test -- tests/graphExpansion.test.tsx tests/graphCoordinates.test.ts。対象ファイルは実装時に作成してから実行する。既存E2Eは環境/fixture設定を読んで対象ケースを選び、いきなり全件起動しない。tscの検査は配布物を生成しない方法を設定確認後に使用する。

S1で合格してからS2/S3へ進む。S4後に旧importを検索し、関連frontend suiteを実行する。既存テストを透過モックに置換して拡大の回帰確認を消さない。

## 6. 証拠と判定

実行中の一時出力はリポジトリAGENTS.mdに従い.temp/graph-expansion/へ集約する。永続的に必要な検証記録は実装タスクに要約し、必要な画像・ログだけfeature/audit-log/graph-expansion/へ保存する。テスト専用fixture以外の個人データは記録しない。

記録する情報:

- 実行日時、branch/HEAD、変更差分、グラフID、pageKey、dataset識別子、列/軸/分析モード。
- ブラウザ・viewport・DPR・ブラウザ倍率・アプリ倍率・scroll位置。
- 期待/実際のrowId集合、論理座標と画面座標、寸法、スクリーンショット。
- host同一性・再マウント回数・解析API要求差分。
- コマンド、終了コード、テスト件数、成功/失敗/skip、既存失敗との切分け。
- S6のbuild実行結果、bundle hashと配信一致、run-production.batからの実画面確認。

判定語は合格/不合格/未実施/N/Aに統一する。必要なケースがデータ不足や起動問題で実施できない場合は未実施とする。対象の削除や代表テストへの置換で完了にしない。V15未実施では「ソース実装・開発環境検証済み、本番起動確認待ち」と記録し、通常buildと本番起動確認まで継続する。完了条件に必須の失敗・未実施が残る間はテスト完了としない。

## 7. ビルド後とレビュー修正後の再検証

通常buildはfullstack/frontendでnpm run buildを実行する。ライセンス検査・TypeScript・Viteの各段階の成否を記録する。run-production.batでhttp://127.0.0.1:8420を開き、最新bundleを配信していることをhash等で照合する。開発サーバでの成功だけでV15を合格にしない。

レビュー指摘の修正後は変更に対応するテストを実施し、配信に影響するソースを変更した場合は必ず通常buildをやり直して本番起動を再確認する。既に成功した無関係な大規模テストの再実行は、変更影響がある場合に限る。報告書のソースsnapshot・テスト・build・配信bundleを同じ修正版にそろえる。レビュー待ちでも、必須検証が不合格となった時点で検証済み状態を取り下げる。
