## 必須の実装仕様

### Menuと分類

- 既存の2段SegmentedをAnt DesignのMenu／SubMenuへ置き換えてください。
- `Menu.items`の親項目をSubMenu、childrenを機能項目としてください。分類→機能の2階層とし、6個の独立したDropdownや独自メニュー基盤を作らないでください。
- 分類は「データ・概要」「可視化」「関係・集計」「パターン探索」「予測・要因分析」「次元削減・因子分析」です。各機能の配置・表示名・順序は設計書3.1の対応表に従ってください。
- 分類keyはgroup:接頭辞、機能keyは既存URLとします。単一の定義から表示、現在地、所属分類、遷移判定を導出してください。機能を利用頻度やデータ型によって並べ替えたり隠したりしないでください。
- 依存関係を追加・更新せず、導入済みAnt Designで利用可能なAPIを使ってください。

### 幅と操作

- 1024 CSS px以上はhorizontal Menu、未満は「機能一覧」ボタンから開くinline Menuとしてください。判定にはAnt Designのlgブレークポイントを使ってください。
- 通常Menuはflex内で縮小可能にし、横スクロールを除去してください。幅不足時は標準overflowを利用し、入口を「その他の分類」としてください。内部overflow keyを固定値で参照しないでください。
- 狭幅では同じ分類定義を使い、分類を1つずつ展開してください。開いた時は現在地の分類を展開し、最大40vhの縦スクロール、長いラベルの折り返しを設けてください。幅の変更で分析画面を再マウントしないでください。
- 開閉はクリックを基本とし、分類を開くだけでは遷移・API呼び出し・分析を発生させないでください。
- 現在地を「分類 › 機能名」で表示し、選択中の機能と親分類を強調してください。

### URL・状態保持

- selectedKeysはlocation.pathnameから導出してください。末尾スラッシュを正規化し、/を/pcpとして扱い、機能URLとは完全一致で判定してください。
- /modelsの前方一致でCAや因子分析を誤選択しないでください。直接URL、戻る・進む、他のボタンからの画面移動にも追従してください。
- 機能項目だけを遷移対象にし、同じ機能の再選択で履歴を増やさないでください。
- URL変更、dataset変更、表示幅の切替、拡大表示への移行時に古いpopupを閉じてください。標準overflow内のSubMenuも操作可能にしてください。
- KeepAlive、実行中解析、結果、入力、描画状態、中央selection、変数、ウェイト、行範囲を維持してください。データセット変更時の既存の再初期化は維持してください。
- 分析ページをMenuの子としてマウントしないでください。分析API、計算処理、データ契約、既存URLを変更しないでください。
- データセット操作、Import／Save／Export、コードブック、License、共通操作、右側の選択行サイドバーを維持してください。

### キーボードとフォーカス

- Ant Design標準のキー操作を使い、Tab、矢印キー、Enter、Escapeで操作できるようにしてください。navに識別可能な名前を付け、選択状態を色だけで示さないでください。
- Escapeで閉じた場合は開いた分類または機能一覧ボタンへ戻してください。キーボードで機能を選んだ場合は表示中の本文へフォーカスを移し、非表示のKeepAlive画面へ送らないでください。

- popupの切れ、画面外へのはみ出し、拡大表示後の残留を防いでください。スタイルはこのナビゲーションへ限定してください。
