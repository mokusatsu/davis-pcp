# 列名の設問文ポップアップとL1色分け拡張

状態: 実装済み（検証記録: [DAVIS-FEAT-028](../tasks/DAVIS-FEAT-028.md)）
詳細仕様・引き継ぎ: [tasks/DAVIS-FEAT-027-028.md](../tasks/DAVIS-FEAT-027-028.md#feature-28-実装仕様)

## 1. 仕様

### 1.1 列名の設問文ポップアップ

コードブック編集画面以外で、実データの列を表す名前・ラベルにポインタを重ねるか、キーボードでフォーカスすると、その列の設問文を表示する。対象は表、列選択、グラフ、解析結果、変数操作ダイアログ、列を含む通知である。

- 内容は先頭に列名、本文に保存済み `CodebookColumn.label` を表示する。
- 既存の列名／ラベル表示モードは維持する。画面上の表示文字列を列の識別子として使わない。
- コードブック未登録、取得中、空文字・空白だけの設問文では「設問文は未登録です」等の仮情報を出さず、追加ポップアップなしとする。既存の省略文字列表示は維持する。
- `label` が列名と同じでも、登録値として存在すれば表示する。
- 同名列が別データセットに存在しても、現在のデータセット以外の設問文を表示しない。
- 編集中の `draftColumns` は参照しない。保存成功で更新し、保存失敗・取消では変更しない。開いているポップアップも保存後の内容に追従する。
- コードブック編集モーダル、その詳細／一覧、CSV取込、一括貼付、値ラベル編集など編集用の子画面は追加対象外。
- PC1、相関係数、rowIdなど、実列に対応しない派生軸・指標名には設問文を付けない。複数の列からなる条件式では各列部分に対応する設問文を付ける。

### 1.2 L1色分け

**型にかかわらず、有効な観測値の種類数が1～20の列をL1候補とする。** numeric列を選択しても数値軸・統計計算・コードブックの尺度は変更しない。

| 有効な値の種類数 | numeric | categorical等 | 表示 |
|---|---|---|---|
| 0 | 対象外 | 対象外 | 欠損のみ |
| 1 | 対象 | 対象 | 1色。候補には表示し、自動選択では複数値の列を優先 |
| 2～20 | 対象 | 対象 | 値ごとの離散色 |
| 21以上 | 対象外 | 対象外 | L1候補に表示しない |

「場合の数」の定義:

1. 読み込んだデータセットの全行を母集団とする。Active／Selected／Sampled、Focus、表示範囲では再判定しない。
2. `null`、`undefined`、数値のNaN・±Infinity、保存済み `missingCodes` を除く。
3. 値コードは既存 `normalizeCode` を使う。数値1と文字列 `"1"` は同じコード、`"01"` は別コード。小数の丸め・ビン分割は行わない。
4. 空文字は `missingCodes` に指定されていなければ1種類とする。文字列 `"null"` と実際のnullは別物とする。
5. コードブックにだけ定義され、実データに出現しない選択肢は数えない。同じ値ラベルでもコードが異なれば別種類とする。
6. 実データ自体の追加・置換・削除やコードブックの欠損定義保存では再計算する。選択スコープだけの変更では色番号を維持する。

## 3. ポップアップの構成

### 3.1 共通部品

`features/common/ColumnQuestionTooltip.tsx` を追加する。入力は列の `nameOrId` と既存表示要素 `children`。列ごとの内容取得には `useCodebookColumn` を使用する。大量の列を描く表・SVGでは、親で一度取得した列参照を渡せるようにし、要素ごとのMap全再構築を避ける。

既存Ant DesignのTooltipを利用し、新しいUI依存は追加しない。静的表示のためのHTML要素とSVG要素を分け、SVGの `text` をHTMLのspanで包まない。部品は子要素のref・イベントを維持する。

表示仕様:

- hoverは約250ms後、focusは即時表示。閉じる猶予は約100ms。
- 上側を基本とし、画面端では反転・位置調整する。幅は最大420pxか画面幅から左右余白を除いた幅。改行を保持し、長い連続文字を折り返す。
- 画面高を超える本文は最大高さを設けスクロール可能にする。ポップアップ上へポインタを移しても閉じない。
- Escapeで閉じる。フォーカスは元の列表示に残す。閉じた直後に同じfocusで再表示しない。
- 元の列表示を `aria-describedby` で本文へ関連付ける。既存操作要素のフォーカスを使い、ボタン・チェックボックス内に新たなボタンを入れない。
- 静的列名にはフォーカスを与える。タッチでは静的列名のタップ、既存操作要素には隣接する設問文表示ボタンを用意し、列選択と説明表示を競合させない。
- 列の並べ替え・チェック切替・ブラシ開始をポップアップ表示が発火させない。スクロール、列の除去、画面遷移、データセット切替で閉じる。
- 設問文はReactのテキストとして表示し、HTMLとして解釈しない。

### 3.2 表示方式ごとの適用

| 表示方式 | 適用方法 |
|---|---|
| 表の見出し、表内の列名、カード、タグ | 表示部分を共通部品で包む。ソートや選択は既存親のまま |
| Selectの候補 | 値と検索用文字列はそのまま保持し、候補の描画だけに設問文を付与 |
| Selectの選択済み値・複数選択タグ | 選択中表示にも適用。削除アイコンと説明表示を分離 |
| Selectのキーボード操作 | アクティブ候補に対応する説明領域を設ける。候補内に余計なTab移動先を作らず、上下キーの候補変更で説明も更新 |
| SVGの軸名・列ラベル | `text` またはそのラベル群をTooltipトリガーにし、既存transformと座標を維持 |
| Canvas内の列名 | 同じレイアウト計算からラベルの当たり領域を生成し、位置合わせしたDOMトリガーを置く。拡大、DPR、スクロール、Focus表示に追従 |
| 行情報など既存のポップアップ内 | 列名の隣／下に設問文を直接併記する。入れ子Tooltipにしない |
| 条件式・複数列の通知 | 列キーが分かる箇所を個別のReact要素で描画。文字列の部分一致による推定置換はしない |

Canvasの対象は少なくとも `pca/BiplotView.tsx` の負荷量ラベルと `qqplot/QQPlotView.tsx` の列名入り軸。PC1等の計算軸には付けない。クリック・ブラシの保護はラベルの当たり領域に限定する。

### 3.3 適用台帳

実装では次のまとまりごとに列の出現位置を記録し、候補・選択済み値・結果の3箇所を別々に確認する。以下は確認対象のファイル群であり、全ファイルを無条件に編集する指示ではない。

| 対象 | 主なファイル・表示箇所 |
|---|---|
| 共通変数選択 | `selection/GlobalHeaderControlBar.tsx` の変数一覧、列入りの選択説明 |
| データ | `dataset/OverviewPage.tsx`、`StatisticsPage.tsx`、`table/TablePage.tsx` の列一覧・ヘッダ・グラフ名 |
| 変数操作 | `AddVariableModal.tsx`、`BinningModal.tsx`、`OneHotModal.tsx`、`ImputationModal.tsx` の既存列参照。新規列名の自由入力は除く |
| PCP・分布 | `pcp/PcpPage.tsx` の設定候補・軸・行情報、`distribution/DistributionPage.tsx`、`QuestionCard.tsx` |
| 可視化 | `relationships/`、`barchart/`、`loess/`、`fedf/`、`covariance/`、`mosaic/`、`qqplot/` の選択・軸・結果 |
| PCA・TGT | `pca/` の入力列・負荷量表・Biplot、`tgt/` の元列ラベル |
| 解析 | `clustering/`、`models/`、`mining/`、`pra/`、`robustness/` の入力・係数／ランキング・条件表示 |

エクスポートしたCSV・画像へのポップアップは対象外。画面上の列名入りメニュー・通知は対象に含める。列参照を保持しない古い履歴文字列から設問文を推定せず、今後生成する表示には列参照を渡す。

## 4. L1のデータフロー

### 4.1 ドメイン生成

`theme/useL1ColorDomain.ts` に、純粋関数 `buildL1Domains(data, codebookColumns)` と、それをメモ化して参照するフックを置く。各候補の情報は `key`、`codes`、`indexByCode`。候補外にはMapを作らない。

全行を走査し、有効コードをSetに追加する。21種類に達した列は走査を打ち切って候補外とする。候補列は全行を読み切る必要がある。行ポインタ移動・描画フレーム内でこの計算を行わない。

色順は次の順序に固定する:

1. 保存済み `categoryOrder` に存在する観測コードを定義順に並べる。欠損と未観測値を除く。
2. 未掲載の観測コードを追加する。numeric列は数値昇順、非numeric列はコードの自然順。同順位にはコード文字列で決定的な順序を付ける。
3. `isReversed` は軸方向なので色順に適用しない。`valueLabels` の文言変更でも色順を変えない。

データ、schemaRevision、欠損／カテゴリ順定義が変わった場合に更新する。共通フックの各利用元が同じ入力で同じ番号を得ることを契約とする。追加の永続Redux状態は作らない。

### 4.2 候補・選択状態

L1候補表示は軸の `type`、可視軸数に依存させない。見出しを「L1色分け：列の値で色分け」、補足を「欠損を除く値が20種類以下の列」にする。候補は既存の表示名に種類数を添え、設問文ポップアップを付ける。

- 手動選択の正本は既存の `pcp.colorBy`。解除はnull。
- 初期自動選択では2種類以上を優先し、既存の正規化エントロピー方式を有効値だけに適用する。1種類しかない列は最後の候補とし、0除算を防ぐ。
- 同一データセット内で有効な手動選択・明示解除をschemaRevision更新によって上書きしない。
- 選択列の削除、21種類以上への増加、全欠損化で無効になったら色分けを解除し、理由を1回表示する。他の列への自動乗り換えはしない。
- 読込途中の一時的なdata=nullでは解除しない。データとコードブックが揃ってから妥当性を判定する。
- 妥当性の監視は `AppShell.tsx` から呼ぶ共通フックに配置し、PCP画面を開いていなくても機能させる。初期化と監視の二重dispatchを避ける。

### 4.3 色割り当てと描画

`theme/viz.ts` にL1専用のlight／dark各20色の固定配列と `l1Color(theme, index)` を追加する。既存のL2・クラスタ用 `entityColor` は維持する。最初の8色は既存L1の表示順と合わせ、9～20色を追加する。単純な8色剰余による繰り返しは使わない。

色トークンの最終値は実装時に20水準の凡例を並べて確認し確定する。受入条件は20色の値が重複しないこと、light／darkで凡例が読めること、L2併用時にも確認できること。20色すべての色覚上の識別を保証するとは記載しない。コード・値ラベルの凡例を併設し、色だけに識別を依存させない。

- `PcpPage`、`useRowColorResolver`、Distribution、Statisticsが同じ `indexByCode` と `l1Color` を使う。
- PCPのpacked下位8bitはL1番号0～19、`0xff`はL1なし。既存のL2ビットと全体コンテキスト `0xffff` は維持する。`catIndex + 1` をやめ、rendererへのL1パレットも同じ0始まりの配列とする。
- 非欠損の同一コードは、行順・表示対象・画面・worker／main threadにかかわらず同じL1色となる。
- 欠損行はL1なしとして描画し、種類数に含めない。L2があれば既存のL2単独合成を使う。分布・ヒストグラムでは「欠損」グループに残し、行数から消さない。
- L2同時適用は現在の色相×輝度合成を維持する。選択・hover・Focusの強調規則も維持する。
- 凡例は共通ドメインの順で「コード／値ラベル」を表示する。値ラベルが同じでもコードで区別する。

## 5. 実装順序

1. 設問文の共通表示部品とL1ドメインの純粋関数を追加し、それぞれ限定テストを行う。
2. 表・共通変数選択・PCPで設問文表示を適用し、SelectとSVGの操作を確認する。
3. 適用台帳に沿って他画面、Canvas、通知を移行する。列名の出現箇所を再検索し、各箇所を「適用／実列でない／編集画面／履歴参照なし」に分類する。
4. L1の候補、自動選択、選択の妥当性監視、専用パレット、PCP packed色を変更する。
5. 共通行色・分布・統計を共通ドメインへ移行し、全利用元の同一行の色を照合する。
6. 実装範囲の検証後に全体テストを行い、`fullstack/AGENTS.md` のL1規定・R6を更新する。

API・コードブックスキーマ・Python解析ロジックの変更は基本的に不要。保存済みデータの形式と座標計算エンジンの入力は維持する。

## 6. 検証と完了条件

### 6.1 限定テスト

- Tooltip: 名前／ID参照、登録なし、空白、多行、HTML風文字列、重複ラベル、別データセット同名列、保存成功／失敗／取消。
- UI: hover、Tab、Escape、Select上下キーと選択済みタグ、タッチで説明表示、ソート・チェック・ドラッグが従来どおり動作すること。
- Canvas: QQ軸・Biplot列ラベルで位置が合い、リサイズ・スクロール・Focus・DPR変更でも対象列を取り違えないこと。
- L1: numericとcategoricalそれぞれ0、1、2、15、16、20、21種類。小数、負数、NaN、Infinity、空文字、missingCodes、未観測の定義値を含むケース。
- 一致性: 同一行についてPCPの `rowColor` と共通resolverの色を比較。Distribution／Statisticsのグループ番号も同じになること。
- 配色: 20個の異なる色番号と20色の重複なし、欠損で通常カテゴリ色を使わないこと。packedのL2ビット・コンテキスト値の回帰。
- 状態: Selected／Sampled／Focus後の色の不変性、データ変更後の候補失効、明示解除の保持、PCP以外の画面でのコードブック保存反映。

既存 `tests/codebookPropagation.test.tsx`、`codebookUi.test.tsx`、`labelAndScaling.test.ts`、`unit.test.ts` の関連範囲を確認し、期待値は変更前の契約と照合する。新規の `columnQuestionTooltip.test.tsx`、`l1ColorDomain.test.ts` に境界条件を集約する。

### 6.2 実画面での受入

1. 適用台帳の各画面で設問文が表示され、コードブック編集画面には追加されない。
2. numericの20種類列を選べて20水準に色が付き、21種類列は選べない。
3. 同じnumeric列の軸位置・範囲・統計値が色分け前後で変わらない。
4. PCP、ペアプロット等の共通resolver利用画面、分布、統計で同じ値の色が一致する。
5. L2、選択、欠損、Focus、データセット切替を組み合わせても描画が破綻しない。
6. 通常起動とstatic／Pyodide起動の双方で保存済み設問文とL1色が反映される。
