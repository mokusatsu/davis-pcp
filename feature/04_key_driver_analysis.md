# 機能仕様書: Key Driver Analysis（Shapley値 / SHAP によるキードライバー分析）

## 1. 概要・目的

アウトカム変数（総合満足度・NPS・ロイヤルティ推奨度など）を動かす要因（ドライバー）を、**多重共線性に頑健な重要度**でランキングする機能。

単純な相関や回帰の β 係数は、ドライバー同士が強く相関すると「重要度の見かけの配分」が歪む（ある要因の寄与が他に吸われる）。Shapley 値（協力ゲーム理論）による R² の公平な分解、または SHAP によるモデル非依存の寄与分解で、**「本当にアウトカムを動かしている要因」**を特定する。

## 2. 位置づけ・依存関係

- 入力はメタデータ付きデータモデル（01 と共通）。
- 出力のドライバーランキングは「感度分析（03）」の `driver_rank` 結論として登録可能。
- 「Penalty-Reward 分析（05）」と組み合わせ、重要度 × 非対称性の優先順位マップを構成できる。

## 3. 入力

- アウトカム変数: 連続（満足度スコア）または順序（NPS を -100〜100 に変換、または推奨度 0-10）。`role == question` からユーザーが選択。
- ドライバー候補: 属性質問のバッテリー（例: 「品質」「価格」「サポート」への評価スコア）。連続・順序・名義（ダミー化）を許容。
- オプション: 重み変数、セグメントフィルタ。

## 4. 手法（3方式を提供、既定は方式A）

### 方式A: Shapley 値回帰（LMG）— 既定

線形回帰の決定係数 R² を、各ドライバーの Shapley 値で公平に分解する。

**R² の分解:**

```
R²(M) = モデル M の説明変数集合の決定係数
Shapley 値 φ_j = Σ_{S ⊆ N\{j}}  [ |S|! (n-|S|-1)! / n! ] × [ R²(S ∪ {j}) - R²(S) ]
```

- `N` は全ドライバー集合、`S` は部分集合。
- `φ_j` は全ドライバーの重要度を表し、`Σ_j φ_j = R²(full model)` を満たす。
- 各 `φ_j` は 0 以上（線形回帰 + 最小二乗なら非負）。

**計算方法:**

- `k ≤ 15`: 全部分集合（2^k）を列挙する厳密計算（`itertools.combinations`）。
- `k > 15`: **Owen 値サンプリング近似**（後述 §4.4）に切り替え。既定のサンプル数 `n_samples = 500`。

**方向（正/負の寄与）の付与:**

Shapley 値は寄与の大きさのみを返す（非負）。方向はフルモデルでの各ドライバーの標準化回帰係数の符号で付与する。

```
direction_j = sign( β_j_standardized )
importance_j = φ_j（R² 寄与、0〜R² の範囲）
```

### 方式B: 相対重要度（Johnson's Relative Weights）— 軽量代替

ドライバーを直交化（正準変数への変換）してから回帰し、R² 寄与を分解する方式。Shapley より高速で安定。`k` が大きい場合や厳密解が不要な場合に提供。

```
X を特異値分解/直交化 → 直交変数 Z を回帰 → β_z の二乗和で寄与を分解 → 元の X に逆変換して重要度を割当
```

### 方式C: SHAP（モデル非依存・非線形対応）— 高度オプション

非線形関係を捉えたい場合、勾配ブースティング等のモデルに SHAP を適用して寄与を分解する。

- モデル: `LightGBM` / `XGBoost` / `HistGradientBoosting`（既定は LightGBM）。
- SHAP: ツリーモデルには `TreeExplainer`（厳密・高速）。線形モデルには `LinearExplainer`。
- 各ドライバーの SHAP 値の絶対値平均 `mean(|SHAP_j|)` を重要度とする。
- 方向は SHAP 値と特徴量の相関（または SHAP dependence plot の傾き）で判定。
- 注意: SHAP は R² 分解ではないため、方式A/B の「R² 寄与率」とは単位が異なる。UI 上は「相対重要度（0-100%に正規化）」で統一表示。

## 5. 前処理

1. ドライバー候補の標準化（z-score）。重要度はスケール不変にしたいため、線形方式では必須。
2. 名義変数は**ダミーコード化**（参照カテゴリを1つ落とす）。順序変数は数値として扱うか、設定でダミー化。
3. 欠損: 既定は listwise（分析に含む変数が全て揃う行のみ）。`n_valid` を記録。代入はオプション。
4. 完全多重共線性の検出: 相関 > 0.95 のペア、または VIF > 10 を警告。完全共線（VIF 無限）は一方を除外して警告。
5. 重み: 線形回帰に標本重み（`statsmodels` の `WLS`）を適用可能。有効サンプルサイズ `(Σw)²/Σw²` を併記。

## 7. パラメータ（設定可能）

| パラメータ | 既定 | 説明 |
|---|---|---|
| `method` | `shapley_lmg` | `shapley_lmg` / `relative_weights` / `shap` |
| `exact_threshold` | 15 | これを超えるドライバー数でサンプリング近似へ切替 |
| `n_samples` | 500 | Owen 値サンプリング数 |
| `bootstrap_ci` | false | 重要度の信頼区間を計算するか |
| `bootstrap_B` | 500 | ブートストラップ回数 |
| `vif_threshold` | 10 | 多重共線性警告の閾値 |
| `corr_drop_threshold` | 0.95 | 完全共線とみなす相関閾値 |
| `missing_handling` | `listwise` | `listwise` / `mean_impute` / `median_impute` |

## 8. エッジケースと対処

| ケース | 対処 |
|---|---|
| 完全共線（VIF 無限） | 一方のドライバーを除外し、除外した旨を警告に記録 |
| ドライバー数 > サンプル数（k>n） | 分析不可。ドライバー削減を促すエラー |
| 全欠損行が大半 | `n_valid` が閾値（既定100）未満なら実行を中止して警告 |
| R² が極端に低い（<0.1） | 結果は参考値扱いとし、「モデルの説明力が低い」警告を表示 |
| 重みで有効 n が激減 | `effective_n < 50` なら警告 |
| 順序変数を数値として扱う妥当性 | 設定で「順序はダミー化」に切替可能 |

## 9. パフォーマンス要件

- 方式A（k≤15）の厳密計算は 2^15=32,768 モデル回帰で、1モデルが高速なら数秒〜数十秒。サンプル数・列数に応じてスレッド並列化。
- 方式A（k>15）は Owen サンプリング 500 回で数秒。
- 方式C（SHAP+LightGBM）はツリーモデル学習 + TreeExplainer で数十秒（10万行 × 100列程度）。

## 10. 依存ライブラリ（Python 想定）

- `statsmodels`（OLS / WLS、VIF、標準化係数）
- `numpy`, `itertools`（部分集合列挙）, `pandas` / `polars`
- `shap`（方式C）, `lightgbm`（方式Cのモデル）
- 相対重要度（方式B）は自前実装（直交化→回帰→逆変換）

## 11. テスト計画

**単体テスト:**

1. 厳密 Shapley 値: 2〜3変数の小さな例で手計算（全部分集合）と一致するか。`Σφ_j == R²(full)` が成立するか。
2. サンプリング近似（k=20）: 厳密解と近似解の誤差が数%以内か。
3. 方向付与: 負相関のドライバーに負の direction が付くか。
4. 完全共線の検出: r>0.95 のペアで一方が除外されるか。
5. 相対重要度（方式B）が 0〜R² に正規化され、合計が R² に一致するか。

**統合テスト（合成データ）:**

6. 既知の寄与（例: 満足度 = 0.6×品質 + 0.2×価格 + noise、品質と価格に相関を持たせる）で、Shapley が真の寄与比率（3:1）をほぼ再現するか。
7. 単純相関では逆転するが Shapley では正しいケース（共線性が高い場合）で、正しいランキングになるか。

**受入基準:**

- 合成データで真の寄与比率との誤差 < 10%。
- `Σφ_j == R²(full)` が数値誤差内（1e-6）で成立。
- k=20 でタイムアウトなし。
